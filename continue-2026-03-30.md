### Bugs Fixed

| Bug | Root Cause | Fix |
|-----|-----------|-----|
| Filter opens automatically | `inputCapture` sent keys to view even during filter | Added `filtering` state, `Filterable` interface |
| Filter doesn't close on Escape | `InputField.DoneFunc` doesn't fire for Escape | `SetInputCapture` on filter input |
| Filter visible by default | Filter row always 1px tall | Start at 0px, `ResizeItem` on `/` |
| Detail modal → jumps to Help | `Pages.RemovePage` falls back to last registered page | `SwitchToPage(viewName)` after remove |
| Overlay file view → Help | Same Pages fallback bug in OverlaysView | Same fix + `modalOpen` state |
| Profile Enter does nothing | `OnKey` didn't handle Enter | Added `showDetail()` with full profile info |
| Selection jumps to row 1 | `renderTable()` used dead `selectedRow` field (always 0) | Save `GetSelection()` before `Clear()`, restore after |
| Centered/unscrollable detail | Used `tview.Modal` (centered, no scroll) | Replaced with `ui.ShowDetail` (full-screen scrollable `TextView`) |

### Design Changes
- **Header**: slim 2-row layout — "w9s.sh" brand + connection info + numbered tabs
- **Theme system**: `internal/ui/theme.go` with `DefaultTheme` struct (modular, DRY)
- **Detail pane**: `internal/ui/detail.go` — scrollable, left-aligned, full-width
- **Form component**: `internal/ui/form.go` — reusable Save/Cancel form with Escape handling
- **ExtraHints**: `ResourceViewConfig.ExtraHints` for OnKeyExtra actions shown in status bar
